# 袁六伟公众号统一交付标准 · 2026-09-14

> 🔴 **2026-11-12 袁总拍板（覆盖下文所有小黑图条款）**：自动化公众号配图**不再使用小黑图 / AI 插画**，尽量全部用真实界面截图、真实成品图、真实后台记录；确需解释抽象关系时只做数据卡/模板卡，且数量控制在少数。发布不再要求文件名含 `xiaohei`/`小黑`。

适用于本人的公众号自动化，不外推到所有设计/写作任务。当前用户明确要求优先；旧 Skill 的杂志封面、native生成中文、每章SVG、固定省token预算、硬凑句式不适用于本工作流。

## 读者与真实性
- 面向普通人、老板和运营者，讲具体场景、材料、动作、结果与检查。自然转述，不用来源报告腔压过文章。
- 真正的朋友口述可以写朋友；网上看到的不能伪装成熟人、对话、见面或亲历。示例/演示简洁标明，不能假造成交。
- 收入保留时间、口径、来源和核验边界。营收不等于净利，报价不等于成交，作者自述不等于审计证明。“范例文章”不能宣传为确证实战。
- 本人身份/课程定位查 Desktop 或 Obsidian已确认材料，不照抄旧Skill中的数字；原内部资料保留，公开版另写。

## 选题、价值与阅读目标

- 每篇以争取2～5万阅读为目标，不承诺结果，也不把内部评分当阅读量预测。质量判断先于制作成本；不能用夸张标题补救没有证据或价值的选题。
- 自由选题时先比较3个有实际材料支持的方向，再选一个：谁正在遇到什么问题、为什么现在关心、有什么新判断或新证据、读完能做什么、会想转给谁。用户指定主题时，在主题内比较切入角度，不擅自换题。选题卡只保留简短结论，不写冗长策划报告。
- 如果只能复述产品公告，缺乏读者场景、独立判断或实际可用的收获，先补材料或缩小承诺。用户指定写资讯简报时按简报完成，不硬塞教程。资料不足就如实交付可写部分及缺口，不虚构案例推进。
- 标题先拟6个有实质差异的候选，覆盖具体困境、可交付结果、证据支持的新判断，再选主标题和2个备选。逐一核对正文能否兑现；数字、亲测、客户结果必须有证据。标题清楚说出读者利益，避免“所有人都要失业”“最后机会”等恐吓与无依据绝对化。候选比较是编辑判断，不声称已经做了真实A/B测试。
- 开头一两个自然段让读者知道：这与我有什么关系、值得继续看什么、依据是什么。可先展示真实结果或具体困境，再展开判断，不以履历、行业空话、重复标题或长背景开场。不要强制每篇都套同一种钩子句式。
- 正文围绕一个中心问题推进，每节增加新证据、新解释或下一步；删掉只是换句话说的重复内容。关键判断回答“依据是什么、读者该如何用、什么情况不适用”，无需机械排成三段。
- 每篇设计一个能带走的核心成果：可复制的任务说明、选择对照表、操作清单、完整拆解、判断框架或有边界的新认识。按题材选最合适的一种，信息正文完整可读，不能只塞进图片或要求加微信才能看到关键答案。
- 分享理由写具体：哪类读者会转给哪类人，帮对方解决什么问题。靠有用的表达和成果产生分享动机，不用奖励、解锁、道德绑架或假紧迫性诱导分享。文末正文先兑现标题，再自然结束或衔接已有产品；保留约定海报，避免每节插广告。

## 发布后的数据闭环

- 优化Skill或写入草稿都不等于文章已经发布。仅在用户要求复盘且有合法可读后台数据、导出表或用户提供数据时执行；不擅自建立定时任务、发送提醒或索要账号密码。
- 有数据时优先看最近10～20篇同账号文章，按题材及发布后相同时间窗口比较；不足就用现有样本并说明限制。没有数据则明确当前方案是待验证的编辑假设，不凭空解释账号为什么没破万。
- 复盘记录实际发布时间、采集时间、统计窗口及指标定义。可比较24小时、72小时、7天的阅读、分享、收藏、关注或咨询等后台实际提供的指标；缺失写“不可得”，不填0。阅读次数与人数不混用，不同口径不直接相除。点击率、读完率仅在后台提供或分子分母一致可算时报告。
- 用同窗口中位数和表现好的文章对照，结合读者反馈提出下一篇可验证的改动。曝光少、点开少、读后分享少是不同假设；没有曝光或阅读深度数据就不能断言封面差或读者中途流失。自然流量的差异不能单凭一篇归因于标题或配色。
- 下一轮优先验证一个主要变量，如切入角度、封面信息或核心成果形态；保留其他基本规范。分别观察2万和5万目标达成情况及真实分享/关注价值，不用刷量、虚构后台截图或阅读承诺达标。

## 内外表达分界（2026-11-03 新增，硬闸）

一句话分界：**读者要不要知道「我们怎么干活」？要 → 对外；不要、只是内部取证/排产 → 对内，不进正文。**

- **不准进正文**：
  - 取证过程：登录墙、未见、未登录、本机怎么截、412、风控、抓不到、一律写、查询日堆的备注
  - 工具元叙事：非本机播放器说明、角标技术说明、截帧路径、证据包路径
  - 产能揭短：整理型、硬闸、没真跑、太忙、本稿未全量实测、产能或业务过满
  - 内部黑话：工作台、media_id、统一事实表、对标方向、按 Skill、对内 SOP 说明
- **公文腔与 AI 味**：本文、笔者、综上所述、首先其次最后；赋能、闭环、抓手、打法、颗粒度、心智、势能、链路、矩阵、生态化、体系化；底层逻辑、本质上、值得注意的是、不难发现、你会发现；「不是…而是…」连用两次以上。
- **可以写**：
  - 干净结论：值不值、怎么选、三步怎么做、适合谁、不适合谁
  - 干净数字 + 来源简称（如「官网价 · 11/03 查」）；没数就删这一行，不用「未见」顶上
  - 画面本身：图说只写「这是什么」，不写怎么截的
  - 可带走物：提示词、步骤、速查表、暗号用法
- **说服力排序**：视频 / GIF ＞ 静图 ＞ 纯文字。能用图说清楚的不写字；判断和数字尽量进图，正文只留衔接和语气。图文比不设上限，宁多勿少。
- **交稿前只问一句**：通读像不像在讲「我们怎么取证」？是就改。
