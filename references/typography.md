## 一、用哪个脚本

| 脚本 | 用途 |
|---|---|
| `scripts/md2wechat_v3.py` | **默认**。克制版：宋体小标题、1px hairline、留白主导、无卡片无图注 |
| `scripts/md2wechat_v2_card.py` | 备选。结构化版：区块头卡片 / 数据卡 / 指令卡 —— **违背宪章「不给每段套卡片」，仅在袁总明确要求时才用** |
| `scripts/md2wechat.py` | v1 历史版，仅留档 |

```bash
python3 scripts/md2wechat_v3.py <发布稿.md> <输出.html> "<预览提示文案>" "../assets/"
```

四个参数：源稿 / 输出 / 预览页提示语 / **图片相对前缀**（预览放 `preview/` 时是 `../assets/`）。

## 二、标记约定（重要）

| Markdown | 渲染 | 用途 |
|---|---|---|
| `**句子**` | **品牌红 #B3002C 加粗** | 关键句（宪章指定） |
| `==短语==` | **墨黑 #1A1A1A 加粗** | 次要强调：小标题式要点、与邻近红句语义重复的、行内短语 |

**为什么要有 `==`**：只有一种加粗时，写完稿会把所有强调都染红 ⇒ 手机预览满屏飘红。
宪章要求「避免连续段落都标红、一段多处标红」，因此需要**两级强调**。

**红字密度（长文）**：12–18 处。超过 20 处就该把「要点提示类」降级成 `==…==`。

## 四、四条不能碰的红线（都踩过）

1. **正文图片不加图注**（用户 2026-09-17 最新要求）。alt 只作属性，不渲染成可见段落。
2. **不给每段套卡片**。金句用红字，不用浅底色块；数据不用卡片框。
3. **不用圆角矩形 / 圆形徽章 / 亮色块**。步骤用「1. 2. 3.」纯文本。
4. **小标题完整不拆**。不要为了好看把「一、xxx：yyy」拆成主副标题。

## 五、已知坑

| 坑 | 症状 | 修法 |
|---|---|---|
| `split_paras.py` 在 `。` 处无条件断句 | `**第一，不用先造产品。** 一颗付费星球…` 被劈成两行 ⇒ 发布稿里**星号裸露** | 已修：切点落在 `**…**` / `==…==` 区间内则跳过。**任何改段落的脚本都要保留这个保护** |
| 三列表格直接输出 | 手机上第一列挤成竖排单字，完全不可读 | 用 `data_table_block` 转两列 hairline |
| 宽横截图直接等比缩 | 手机里字只有 7px，等于没证据 | 裁到内容区（目标图宽 ≤900px）；**超长页面拆局部，别把整页缩成细条**（宪章原文） |
| 对外文章里的工作截图含本机路径 / 内部措辞 | 暴露 `/Users/…`、`xx.py`、「需袁总点头后执行」「A 表」等 | 上传前逐张 OCR 检查，打码或裁掉；**学员的帖子标题/topic_id 一律不出现在公开图里** |
| 预览 HTML 被浏览器缓存 | 改了样式但截图没变，误判成"没生效" | 截图时给 URL 加 `?cachebuster=<ts>`；或用 `getComputedStyle` 实测颜色，别只看像素 |
| 图注把小黑图写成「真实操作」 | 违背「示意和证据明确区分」 | 判据要同时看**文件名和 alt**（`10-小黑-xxx.png` 的 alt 里常没有「小黑」二字） |

## 六、验收动作（每次排版后必做）

```bash
python3 scripts/preflight_check.py <发布稿.md> <预览.html>
```

四查（不通过不放行）：

1. `残留裸星号 = 0`
2. 浏览器同源统计红色 `strong` 数量，落在 10–20
3. 376px 宽预览截图**落盘**（没截图 = 没做验收）
4. 正文截图逐张 OCR：拦本机路径 / 内部脚本名 / 内部措辞（`需 xx 点头`、`A 表`）/ 学员隐私（他人帖标题、topic_id）
