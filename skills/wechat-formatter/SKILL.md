# 公众号手机排版 · 汇芯红六套骨架

正文排版**唯一来源**是本 skill 的 `themes/` 目录（来源：`sixwei2025/ai-tool-review-wechat-skill`，MIT，2026-11-02 并入）。袁六伟主号任务仍先读 `../wechat-auto-publisher/references/editorial-contract.md`：**骨架管版式，契约管内容与证据**，两者都不许跳。

`../wechat-auto-publisher/references/组件库.md`（旧 `:::` 红白组件）已降级为**兜底**，只在主题文件明确没有等价组件、且手工装配来不及的时候用，不作为主路径。

## 一、选骨架：按内容选，不按星期（2026-11-12 袁总拍板）

🔴 六套骨架**不是**按周一到周六轮着用，是看这篇内容的结构、长度、框架来定。按天轮换的旧规则已废止。

| 内容特征 | 选哪套 | 开篇形态 |
|---|---|---|
| 长教程 / 清单 / 工具盘点 / 高密度信息、图多 | `magazine-card` | 杂志快讯封面 + 横向目录 |
| 深度分析 / 观点 / 力量感话题 | `classic-edit` | 引言卡 + 编号章节 |
| 设计 / 科技评论 / 短观点 | `minimal-line` | 细线金句 |
| 深度随笔、情绪性文字、图少 | `zen-space` | 衬线大字 |
| 测评 / 工具对比 | `ticket` | 门票封面 |
| 案例复盘 / 系统性说明 | `journal` | 内刊头图 |

判定顺序：先看信息密度和图量 → 再看有没有清单/代码块 → 最后看情绪浓度。同日多篇才考虑换一套，但不为换而换。**不许反问用哪套**，选题材匹配的那套并在 STATUS 写一句理由。
⛔ `zen-space` 组件库明确写着「教程/清单弱契合，建议换主题」，长清单文别选它。
⛔ 转换器 `--theme auto` 仍按星期，是兜底；**正式稿必须显式传 `--theme <id>`**。
⛔ 转换器只出「主题化基础版式」，主题专属开篇封面/目录/章节标题/END 不硬编码，**转换后必跑**：
`python3 ~/.workbuddy/scripts/apply_theme_shell.py --article article.base.json --theme <id> --out article.local-images.json`
缺了这步 = 六套排成同一套普通正文，校验器会直接拦下。

**一篇只用一套，不混搭。**

## 三、硬约束（六套骨架之上叠加，不许为了版式让路）

- 🔴 **只用真实截图，不用小黑图**（2026-11-12 袁总拍板）：普通篇幅以 8–12 张有效真实界面截图/真实成品图为主力，紧跟对应事实/操作。没有界面可截时，才用少量数据卡/模板卡补位并标明是整理示意。不再生成 AI 插画，不再要求图名含 `xiaohei`/`小黑`。封面和文末海报不计入正文配图数量。
- **短段落**：一段展开一层意思，2–3 行（约 40–60 字）为常态；过密参考上限 80 字（超了提示密度，不为过检截断论证）。主题正文行高按各主题速查表，不擅自统一成一套。
- **小标题完整可扫读**：`## 01 判断句` 这类，不只留编号；标题文字不许只剩数字。
- **文末海报**：正文最后默认插入 `../wechat-auto-publisher/assets/ending-poster-product.jpg`（《袁六伟 · 一人AI公司》产品介绍海报，**不带二维码**），复制进文章 assets 后实际插入并上传，不改写内容。🔴 2026-11-03 起停用带二维码的 WorkBuddy 一人公司营海报（`default-ending-poster.jpg`），带二维码会被平台限流。用户明确取消或给新图时按最新要求。
- **图注口径**：12px（≤13px）、灰色（`#A3A3A3`/`#9CA3AF`/主题灰）、**居中**；禁止用正文字号正文色冒充图注。默认优先空 alt 不写图注；确实需要说明时才用图注样式。
- **金句标红克制**：汇芯红 + `font-weight:600`，每篇 3–6 处；不整段染红、不给每段套卡片。`minimal-line` 全篇 ≤3 处、`zen-space` 只点缀。
- **平台红线**：只写内联 `style`；禁 `<style>/<script>/<div>`、`class`/`id`、`position:fixed/absolute/sticky`、`float`、`@media`/`@keyframes`、`display:grid`、CSS 变量、外部字体。照抄主题文件时保留其 `<span leaf="">` 包裹与装饰性空元素的 `<span leaf=""><br></span>` 占位，删了微信会剥样式。
- **乱码硬闸**：推箱前自查——无双重转义 `&amp;quot;`、无残留 Markdown 反引号、无 `linear-/radial-/conic-gradient`、图说走 12px 灰字居中、金句 3–6 处。
- **不另创封面**：用总控/盖有面的封面成品，不轮换杂志模板，不重复正文 H1，不自动每章生成 SVG。
- 不给用户只丢一堆需要手动操作的 HTML；已授权就直接做到草稿箱。

## 四、转换与装配

主路径（推荐，可复现）：

```bash
python3 ../wechat-auto-publisher/scripts/markdown_to_wechat_article.py \
  --md article.md --title "标题" --theme magazine-card \
  --content-image 01-xxx.png --content-image 03-xiaohei-yyy.png \
  --out article.local-images.json
```

- `--theme` 取六套 id；**省略则按当天星期自动轮换**（等价 `auto`）。`--list-themes` 打印 id/中文名/适用场景/当日默认。
- 脚本产出「主题化基础版式」：全局容器、正文、小标题、引用/重点条、条目红点、代码块、图注、`:::` 组件都按该主题 token 取值。
- **主题专属的开篇卡/头图卡/票据封面等重装饰模块**，脚本不硬编码：按 `theme-<id>.md` 的组件 HTML **手工替换文章顶部那一块**（该块是骨架的身份，不能省略、不能套用到别的主题）。替换后正文其余部分仍走脚本，不整体手写。
- `:::` 高级组件语法（`quote` / `stat` / `tag` / `end` / `compare` / `step`）保留可用，颜色随主题 token；结构定义仍在 `../wechat-auto-publisher/references/组件库.md`。

手工装配兜底：主题文件里的 HTML 可直接粘进草稿，但必须整段来自同一主题，且仍要过校验脚本。

## 五、转换细则（沿用，勿改坏）

- 图片写法 `![图注](image.png)` 或 `[[img:image.png]]`，放在准确位置；`--content-image` 是「已放置」声明，未指定位置要报错，不擅自排到末尾；**未放置的图不许堆文末**。
- **正文图 src 必须用 basename**（`03-xiaohei-job-card.png`），不能带 `assets/` 前缀：上传时正文图平铺到远端同目录，校验器只按 `article_path.parent/src` 找图，带前缀会 exit 2 让整个 add 中止（2026-09-15 实际踩到）。
- `body_lines` 只取 `## 正文` 之后的内容：来源、真实性说明、内部审稿备注一律写在 `## 正文` **之前**，否则会被排进正文发出去。
- 不把正文第一行默认识别为标题并删除；不重复 title；连续 `>` 合并轻块，全是 `-` 的引用块逐条红点；Markdown 链接转安全 http(s)。
- **配图零灰字图注 + 告别「原件一二三」拥挤框（2026-11-13 袁总拍板）**：
  - **配图下方不留灰色小字**：`markdown_to_wechat_article.py` 不再渲染 `![alt](img.png)` 的灰色图注，并自动忽略图片下方紧跟的 `（...）` 说明行，让画面干净利落；
  - **严禁「原件 1/2/3」与图文重复堆砌**：凡是配图已经清晰展示的秘籍卡、目录表或流程，**严禁在下方再塞 `【原件 1】`、`【Prompt 1】` 等拥挤文字框**；
  - **短指令与命令极简渲染**：纯中文短指令自动渲染为米白底红左边的 1–3 行清爽引文框，纯终端命令渲染为无顶部冗杂栏的 1–4 行 `$` 命令框，校验器强制拦截 `【原件/Prompt...】` 字样与 >320 字灰框。

## 六、检查

1. 转换后跑统一校验器（上传入口同样显式传 80）：

```bash
python3 ../wechat-auto-publisher/scripts/validate_wechat_article.py \
  --article article.local-images.json --max-paragraph 80
```

校验含：重复标题、裸数字小标题、占位符残留、本地路径、缺图、段落过密、forbidden-tags、半角标点，以及**乱码硬闸**（双转义、反引号、gradient）与**图说样式软检查**。

2. 375px 手机预览逐屏过：正文密度、截图是否要反复放大、图是否只是重复文字、骨架是不是被排成同一套红白。用预览看密度，**不把字数校验冒充实屏验收**；做不到就标「未完成视觉验收」。
3. 旧长文只在用户要求修改时处理，不批量改历史文章。

- **2026-11-03 开篇三件套去重（踩过坑，必查）**：骨架的开篇形态（引言卡金句 / 大字开场 / 头图卡）**本身就是开场**，正文原来的第一段必须让位。
  装配骨架后逐条核对三个开头，语义不许重叠：
  1. **引言卡金句**——卖「核心结论是什么」
  2. **正文首段**——如果没有独立存在的价值（比如它其实在复述第一个章节标题），**直接删掉**，不要保留
  3. **第一个章节标题**——卖「这一段讲什么」
  ❌ 典型错误（2026-11-03 实际发生）：引言卡放「技巧在贬值，判断在增值」→ 正文首段写「我拿同一个模型，让两个人写同一份周报」→ 第一章标题又是「同一个模型，两个人写周报」，同一件事说了三遍。
  ✅ 正确形态：引言卡金句 → 本文看点 → 第一章标题 → 直接进场景细节。
  这条**不能靠 grep 结构通过**：查到「引言卡存在」「章节替换成功」不等于开头成立，必须看 375px 实际渲染的前两屏。

- **2026-11-03 尾件清单（同样踩过漏）**：装配骨架时首尾都要过一遍，别只装开头和章节。以 classic-edit 为例，文末至少要有：
  1. **组件 15 END 分割线**——红渐变短线 + END 字样
  2. **组件 16 三连引导**——「如果你觉得今天这篇有收获，欢迎**点赞、在看、转发**三连，我们下篇见。」（「点赞、在看、转发」用 `#C8102E` 加粗，`<strong>` 上不加 `font-size`）
  3. **文末海报**——产品介绍版 `ending-poster-product.jpg`
  顺序：正文 → END → 三连 → 海报。海报**不配图注**（不要在海报下面写「袁六伟 · 一人AI公司」这类文字）。
  ❌ 2026-11-03 实际漏过：只装了引言卡/看点/章节标题，END 和三连整个没装，海报下还多了一行图注。
